> **О коде.** Этот репозиторий описывает методологию, ключевые решения и результаты. Реализация является собственностью компании, в которой создавался проект, и не публикуется.

Два связанных инструмента, заменившие полностью ручную разметку текста: LLM-разметчик с памятью и устойчивой пакетной обработкой, и построенный поверх него самообучающийся генератор регулярок, который учится ловить те же сообщения дешевле — вообще без обращения к LLM.

## Кратко

| | |
|---|---|
| **Экономия времени IA (разметчик)** | ~70% |
| **Ускорение на повторных датасетах** | 3–5× |
| **Исправление ошибок вторым кругом** | 3–7% элементов |
| **Целевой порог сходимости регулярок** | ≤5% ложноположительных |
| **Итераций до сходимости** | ~10 |
| **Статус** | закреплена как внутренний инструмент; разработка передана команде, развивающей сервисы автоматизации чат-бота, как кандидат на отдельный сервис |

## Проблема

Разметка текста для инструментов чат-бота — иногда более 1000 триггеров на датасет — выполнялась вручную интент-аналитиками. Это было медленно, монотонно и плохо масштабировалось с ростом датасетов.

## Часть 1 — LLM-разметчик с памятью

**Что делает.** Классифицирует входящий текст как подходящий / неподходящий под класс через LLM с продуманным промтом, решая при этом операционные проблемы, из-за которых пакетные LLM-задачи на практике легко ломаются:

- **Память (SQLite).** Уже размеченные тексты сохраняются и отфильтровываются перед повторной отправкой в LLM — без лишних вызовов и лишних затрат.
- **Устойчивость.** Ошибки лимита токенов автоматически ставят задачу на паузу и продолжают её, а не обрушивают весь прогон.
- **Выборочная очистка.** CLI-флаг `--clear` поддерживает очистку всех / только положительных / только отрицательных меток — повторные прогоны не требуют старта с нуля.
- **Второй круг проверки.** Дополнительный проход перепроверяет только изменившиеся с прошлого прогона элементы, отлавливая ещё 3–7% ошибок разметки без повторной обработки всего датасета.
- **Логирование.** Каждая операция логируется в читаемом формате, а не просто как счётчик успех/ошибка.

## Часть 2 — Самообучающийся генератор регулярок

**Зачем.** Даже оптимизированный по стоимости вызов LLM дороже, чем совпадение по регулярному выражению. Этот инструмент автоматически пишет и уточняет регулярки на основе тех же размеченных примеров, чтобы ловить те же сообщения дёшево и оставлять LLM только для случаев, которые в этом действительно нуждаются.

**Как это работает.** Цикл на схеме выше: начальная регулярка строится по размеченным положительным и отрицательным примерам, прогоняется по датасету, и каждая ложноположительная/ложноотрицательная ошибка возвращается обратно в процесс генерации более точного набора паттернов. Это повторяется — как правило, порядка десяти итераций — пока доля ложноположительных срабатываний не опустится до целевого порога ≤5%. Та же память из Части 1 держит каждую итерацию быстрой, поскольку уже размеченные примеры не нужно заново выгружать и переоценивать с нуля.

**Ограничение, которое стоит назвать честно.** Расширение или сужение регулярки для исправления одного типа ошибки может сдвинуть то, что она ловит или пропускает в целом — поэтому цикл спроектирован так, чтобы на каждой итерации расширять пул размеченных примеров, а не подгонять правило под один и тот же фиксированный набор.

## Результаты

- Примерно 70% сокращение времени интент-аналитиков на ручную разметку, с ускорением в 3–5× на датасетах, пересекающихся с уже размеченными данными.
- Второй, точечный круг проверки отлавливал ещё 3–7% ошибок разметки при незначительных дополнительных затратах.
- Слой регулярок усиливает эту экономию ещё больше: любое сообщение, которое регулярка может уверенно классифицировать, вообще не требует вызова LLM — поверх экономии, которую даёт сам разметчик.

## Влияние на бизнес

- Повышена автоматизация ранее ручного процесса, снижены и время аналитиков, и стоимость классификации на сообщение.
- Ускорен выход в прод новых размеченных датасетов.
- Повышена точность за счёт дешёвого второго прохода проверки без дообучения модели.
- Размеченная база SQLite в теории может использоваться как обучающий датасет для других моделей — на практике это не было реализовано, но данные структурированы так, что это возможно.
